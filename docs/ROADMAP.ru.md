Проект слишком большой для одной спецификации, поэтому разбит на этапы. Каждый этап —
самостоятельный под-проект со своим циклом «спека → план → реализация» и **работающим
результатом в конце**. Порядок выбран так, чтобы риски снимались раньше всего.

## M0 — Ядро: одна сессия под управлением сервера (1-й под-проект)

Снимает главный технический риск: управляемая долгоживущая сессия.

- pnpm-монорепо: `server`, `web`, `shared`.
- SessionManager на Agent SDK (streaming-input): старт, стрим событий, interrupt, resume после рестарта сервера.
- SQLite event-log + WebSocket replay-then-tail.
- Минимальный web-UI: один чат с агентом, карточки аппрувов (`canUseTool`).
- Один аккаунт (текущий `~/.claude`).

**Готово, когда**: сессию можно вести из браузера, убить сервер и продолжить с того же места.

## M1 — Цех: 3D-фабрика, проект-блок, комнаты

- 3D-сцена (react-three-fiber, изометрическая камера, low-poly): главное здание =
  проект (по клику — CLAUDE.md/README), создание комнат-цехов → папок, конвейерные
  дорожки между зданиями.
- 2D-оверлей: **taskpanel** (ручное создание тасков, пока с ручным выбором отдела),
  панель комнаты (charter, выбор модели/скиллов/MCP per-агент), статусы
  working/idle/blocked на зданиях.
- **Библиотека ролей v1**: ~10 стартовых пресетов (архитектор, backend, frontend,
  дизайнер, QA, DevOps…) — роль = промт + скиллы/superpowers + плагины/MCP + модель;
  назначение в один клик, файловый формат `roles/*.yaml` (расширение до 50+ ролей и
  пользовательских пресетов — в M5).
- Агент-онбордер для пустого проекта (интервью → документы).
- ~~Layout сцены сохраняется в `.fabrica/layout.json`.~~ **Так не сделано**: позиции комнат
  живут в колонках `rooms.pos_x`/`pos_z` в самой SQLite-базе. Отдельного `layout.json` нет.

## M1b — Проекты, папки, файлы и настоящий UI

Четыре вещи, которые запросил оператор, когда цех уже стоял. Сгруппированы, потому что все меняют одну и ту же поверхность: на что смотрит браузер и как человек кладёт туда вещи.

- [x] **Много проектов в одной Фабрике.** Папка проекта выбирается в UI, между проектами можно переключаться; у каждого свой цех со своими комнатами, агентами, тасками, сообщениями и историей. Всё скоупится `project_id` в одной базе, переключение мгновенное и без рестарта сервера. `SUPERFABRIC_PROJECT` становится дефолтом первого проекта, а не единственно возможным.
- [x] **Рабочая папка комнаты.** По умолчанию `<проект>/<имя>/`, но папку можно указать любую — отдел может жить в отдельном репозитории. Усыновление существующей папки никогда не перезаписывает её `CLAUDE.md` (инвариант уже соблюдается — сохранить).
- [x] **Файлы внутрь, пути наружу.** Вставка из буфера, drag-and-drop на окно, загрузка. Файл пишется в папку проекта (или выбранной комнаты), а агенту улетает **путь**, не байты. Картинкам из буфера даётся вменяемое имя и расширение.
- [x] **Настоящий UI.** Перевести HUD с рукописных inline-стилей на библиотеку компонентов, чтобы панели выглядели спроектированными, а не собранными. Выбор и обоснование — `docs/decisions/0003-ui-library.md`.

**Приёмка первых двух пунктов (2026-08-04, ни один агент не промптился)**: два проекта в одном сервере — `factory-a` (три комнаты) и `Factory B` (две), в базе у каждого есть комната с одинаковым именем, свой борд и своё сообщение в очереди шины. Переключение в HUD переводит камеру и перерисовывает цех: только его здания, только его борд, только его ленты; комната, созданная во вкладке одного проекта, не появилась во второй вкладке, смотрящей на другой. Комната с явно указанной папкой вне корня проекта усыновила чужой репозиторий, не тронув его `CLAUDE.md`, а созданный там агент записал эту папку как свой `cwd`. Перенацеливание комнаты не сдвинуло `cwd` уже работающего агента даже после рестарта сервера — именно об этом предупреждает панель. 539 тестов зелёные (shared 39, server 297 + 1 пропущенный live-quota, web 203).

## M2 — Мульти-аккаунт и монитор лимитов

- AccountManager: профили через `CLAUDE_CONFIG_DIR`; при создании комнаты/агента выбираешь, под каким аккаунтом он работает. ~~кнопка «Добавить сессию» — встроенный терминал (xterm.js ↔ node-pty)~~ — **сделано иначе**: `claude auth login` вообще не требует TTY, поэтому вход — это ссылка и поле для кода, без xterm.js и без node-pty (см. [решение 0004](decisions/0004-account-login-over-a-pipe.md)).
- LimitMonitor: поллинг OAuth usage endpoint по каждому аккаунту, метры 5h/weekly/per-model в UI, перехват 429.
- Scheduler: предупреждение агентам на 80%, пауза на 95%, авто-resume по `resets_at`.

**Готово, когда**: 2+ аккаунта работают параллельно, пауза/возобновление по лимитам — без участия человека.

## M3 — Шина фабрики и оркестратор

- Factory Bus: in-process MCP-инструменты (`factory_send`, `factory_inbox`, `factory_report_status`, `factory_task_update`, `factory_ask_orchestrator`), push-доставка инжектом turn'а.
- TaskStore + канбан-панель + бейджи тасков на комнатах.
- Оркестратор: выделенная сессия (Opus) с обзором всех комнат, распределением задач, снятием блокеров; консоль оркестратора в UI.
- **Авто-роутинг тасков**: таск из taskpanel без выбранного отдела уходит оркестратору — тот анализирует, назначает отдел и ответственного, отправляет в работу.
- **Chronicle v1 (летопись решений)**: инструменты `factory_record_decision` + `factory_search_history`, ADR-файлы в `docs/decisions/`, FTS5-поиск по решениям и истории промптов/событий, таймлайн в UI.
- Коробки-сообщения едут по конвейерам между цехами (анимация вдоль сплайнов).

## M4 — Контейнеризация

- Образ `agent-runner` (Node + SDK + claude), dockerode-менеджмент.
- Один контейнер на комнату; mount профиля аккаунта и workspace; egress-firewall по референсу Anthropic; лимиты ресурсов.
- `--dangerously-skip-permissions` внутри песочницы + правила автоаппрува per-room.

## M5 — Полировка и «живая фабрика» ✅ закрыт (2026-08-04)

- [x] Маленькие агенты-человечки в цехах и living-factory детали (дым из труб, свет в окнах,
      ползущие ленты, реквизит по профилю комнаты, «мысли» над головой работающего). **Но
      glTF-персонажей сознательно не покупали**: движение процедурное и выведено из
      event-log'а — это информативнее статичного меша и не тащит чужие лицензии в MIT-репу.
      Причины — в M5-секции [ROADMAP.md](ROADMAP.md).
- [x] Метрики: burn-rate по аккаунтам («при таком темпе у тебя примерно три часа», а при
      недостатке истории — честное **unknown**) и стоимость-эквивалент по аккаунтам и
      комнатам. **Никакой таблицы цен в проекте нет** — цифру даёт сам CLI.
- [x] Экспорт/импорт фабрики (мульти-проектность переехала в M1b). В файле нет ни секретов,
      ни абсолютных путей; аккаунты едут ярлыками и привязываются заново при импорте.
- [ ] **Нотификации (push на телефон) — не сделано.** Никакой поверхности уведомлений вне
      вкладки браузера не существует. Прямой чат с агентом есть с M0.
- [ ] **История/поиск по событиям** — есть в виде летописи (FTS5 по решениям *и* по тому, что
      агенты говорили), отдельного «поиска по событиям» сверх этого нет.
- [ ] **Подсчёта токенов на ход нет**: в логе лежит только `costUsd`, поэтому ccusage-подобной
      токен-аналитики не построено. Burn-rate её и не требует — он считается по реальным
      показаниям утилизации.

- **Мульти-провайдерные исполнители**: Codex / ChatGPT-агенты, Antigravity (Gemini) и другие за интерфейсом `Executor` (существует с M0) — разные силы под разные таски и комнаты. **На сегодня реализаций две и обе гоняют Claude Code** (в процессе сервера и в контейнере); второго провайдера нет.

## Вне скоупа v1
- Мультитенантность, облачный деплой, командный доступ.
- Автоматическая ротация аккаунтов ради обхода лимитов — сознательно НЕ делаем (ToS-риск); только пауза/resume своих аккаунтов.
