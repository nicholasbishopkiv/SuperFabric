# Фабрика (SuperFabric)

> 🇬🇧 English version: [README.md](README.md) — **канонический документ**. Этот файл
> поддерживается вручную и короче английского: если два текста расходятся, прав английский.

**Self-hosted визуальный оркестратор мульти-аккаунтных Claude Code агентов.**

Браузерное приложение-«завод»: изометрическая 3D-сцена, в центре — здание проекта, вокруг — цеха-отделы (backend, frontend, devops…). В каждом цехе живут агенты — отдельные сессии Claude Code, привязанные к разным подписочным аккаунтам; при желании каждый цех можно перевести в свой контейнер. Отделы общаются через MCP-шину фабрики, старший агент-оркестратор раздаёт работу, а UI показывает в реальном времени: кто работает, кто ждёт, кто упёрся в лимиты и когда они сбросятся.

## Зачем

- **Согласованность команд-агентов**: один проект, много зон ответственности, общее понимание «куда движемся». Комната просит другую комнату о чём-то через шину и получает ответ, когда работа сделана.
- **Мульти-аккаунт**: 2–3 подписки Claude (Pro/Max) работают параллельно, лимиты видны по каждой, у порога агенты предупреждаются, на пороге — ставятся на паузу и сами возобновляются после сброса окна. **Ротации аккаунтов ради обхода лимитов нет и не будет** — это осознанная граница (ToS).
- **Визуализация**: открытые таски, блокеры, переписка отделов — на одном экране, поверх живого цеха.
- **Библиотека ролей**: **11 готовых пресетов** (architect, backend, data, designer, devops, frontend, generalist, qa, security, tech-writer плюс `onboarding`, которую фабрика надевает на агента сама). Это обычные YAML-файлы в [`roles/`](roles/README.md) — их можно форкать, а `<каталог данных>/roles/` переопределяет любой из них по `id`.
- **Летопись решений**: ADR-файлы в самом репозитории плюс полнотекстовый поиск по ним *и* по тому, что агенты реально говорили.
- **Burn-rate, а не «сколько токенов»**: рядом с метрами лимитов — «при таком темпе у тебя примерно два часа», посчитано по наклону реальной истории показаний. Если истории мало, честно пишется **unknown**, а не выдумывается число.
- **Перенос фабрики**: экспорт цеха (комнаты, штат, борд, индекс решений) в один JSON и сборка его в другом месте. **В файле нет никаких секретов**: аккаунты едут только ярлыками, которые ты заново привязываешь при импорте.
- **Аккаунты добавляются из UI**: ссылка на вход и поле для кода, который выдаёт страница Claude. Никакого встроенного терминала — `claude auth login` не требует TTY, см. [решение 0004](docs/decisions/0004-account-login-over-a-pipe.md).

## Статус

**M0–M5 закрыты** (2026-08-04): ядро сессий, 3D-цех с комнатами-папками, несколько проектов
в одном сервере, мульти-аккаунт с монитором лимитов и паузой/резюмом, шина + борд +
оркестратор + летопись, библиотека ролей и агент-онбордер, контейнер на комнату, burn-rate
метрики и экспорт/импорт фабрики. **1 344 теста зелёные.**

**Чего сознательно нет** — пуш-уведомлений на телефон, выбора папки диалогом вместо
текстового поля, других провайдеров-исполнителей, расширения библиотеки до 50 ролей и
прочего — перечислено в конце [docs/ROADMAP.md](docs/ROADMAP.md#what-is-not-built).
Прочитай этот список прежде, чем предполагать, что фича есть.
